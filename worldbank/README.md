# World Bank PAD to IEG outcome backtest

The first leakage-controlled public join from a World Bank project's appraisal
document (the proposal, written before approval) to IEG's independent outcome
rating (the verdict, written years later), plus a forward-chained text baseline.

This is one of three procurement backtests for Thesis Institute. The question it
answers: **how much of an official evaluator's later verdict is already legible
in the proposal document at the moment of approval?**

## Quick start

```bash
make test      # pytest: label construction, leakage filter, scoring functions
make all       # fetch everything, build the join, download text, model, analyse, report
```

`make` is not available everywhere (it refuses to run on this machine until the
Xcode licence is accepted), so the same pipeline, in the same order, is also a
plain script:

```bash
./run_all.sh              # full pipeline including the network fetches
./run_all.sh --no-fetch   # everything downstream of the raw data already on disk
```

Any single step is a module: `.venv/bin/python -m worldbank.src.<name>`.

Read `results/report.md`. It is standalone.

## The result, up front

**The joined dataset is the contribution. The model is a weak positive that has
not been replicated.** Exact figures live in `results/report.md` and are
regenerated by the pipeline, so they are deliberately not restated here.

- One rung, PAD text alone, beats a constant forecast at the realised test base
  rate on Brier score. That benchmark is the strict one, since no forecaster
  could have known that base rate in advance. Every other rung is worse than the
  constant.
- PAD text alone does rank outcomes slightly better than chance within country,
  and clears an exact within-country permutation null at p below 0.05.
- That p-value is uncorrected across six rungs and a nine-point regularisation
  sweep, and pure-noise refits of the same pipeline land close to it. Read it as
  a reason to run one pre-registered replication, not as a finding.
- A model given nothing but the country identity gets most of the naive pooled
  AUC, and exactly 0.500 within country. That is why every table shows both.

## What the audit changed

The code was audited adversarially after the first complete run: six independent
reviewers, 48 findings, each handed to a separate skeptic instructed to refute
it, 22 surviving. The fixes that changed a number or withdrew a claim are listed
in `PROGRESS.md`. Four are worth knowing before reading anything else:

1. **A post-treatment feature was removed.** `ieg_country_fcs_status` tracks a
   project's closing period, not its approval period (`src/feature_vintage.py`
   measures it). The headline rung uses no structured feature, so the headline
   is unaffected either way, and the sensitivity is reported.
2. **A false mechanism claim was withdrawn.** The code asserted that the API's
   `curr_` prefix distinguishes current from approval-time amounts. It does not:
   `lendprojectcost` and `curr_project_cost` are the same number on 100% of
   rows. So `log_commitment` has UNKNOWN vintage, and the report says so.
3. **A caveat was measured and turned out backwards.** "Older documents are
   scanned and OCR'd, noisier before 2005, which is the training fold" is wrong
   twice: the noisy block is 2004 to 2009, and it lands in the VALIDATION fold,
   which is where the regularisation strength is chosen.
4. **The filter was preferring translations.** It kept a French, Spanish, Arabic
   or Russian version as "the" appraisal document for 40 projects when an
   English original existed for 39 of them. It now prefers English among the
   documents that pass the date test.

## The three things worth knowing before reading the numbers

**The leakage the filter removes.** Additional-financing appraisal documents and
restructuring papers share the P-number of the original project and are dated
after board approval. A document written three years into implementation can
describe what already happened. The filter keeps, per project, the earliest PAD
dated on or before board approval plus 30 days, and counts everything it drops.

**The country effect.** Pooled AUC on this data is substantially an artefact of
some countries succeeding more often than others. The report always shows
within-country AUC next to the pooled figure, and the within-country number is
the one that answers the question.

**Two measured defects in the Projects API `icr_ratings` block.** It is returned
as a denormalised cross product, and it emits "Substantial" where the rating is
"Satisfactory". Both were established by measurement against a second published
source, not assumed; see `src/icr_selfrating.py` for the evidence and the limit
of the claim.

## Data

Nothing here is redistributed. `make all` fetches from:

- Finances One DS00053 / RS00055, IEG World Bank Project Performance Ratings,
  12,598 rows by 21 columns, CC BY 4.0
- World Bank Documents and Reports API v3 (`search.worldbank.org/api/v3/wds`)
- World Bank Projects API v3 (`search.worldbank.org/api/v3/projects`, `fl=*`)
- Data Catalog dataset 0038056 resource DR0095723, the Digital Governance and
  GovTech Projects workbook

Raw downloads land in `data/raw/worldbank/` and are gitignored. The PAD text
corpus is roughly 1 GB.
